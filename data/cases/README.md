# 业务规则边界案例

`boundary.jsonl` 是 32 个独立的模拟业务资格案例，每行一个 UTF-8 JSON 对象。金额使用 CNY 整数分，时间有明确时区；通常使用固定业务时间 `2026-09-17T12:00:00+08:00`，政策边界与时区等价案例明确给出自己的时钟。

每行包括：

- `case_id`：稳定的业务案例标识。
- `rationale`：手工核对输入及期望的依据。
- `input`：完整订单快照或 null、业务动作参数、业务时间和可信的澄清事实。
- `expected`：手工写定的完整 RuleDecision，包含是否符合资格、原因代码、规则与政策版本、正确金额及可用转人工原因。

订单快照从模拟业务订单派生，各案例互相独立；例如已退余额仅表示待评估事实，不用于直接初始化账本或改写订单。动作政策引用使用版本化业务规格引用，不能作为检索文档引用或人工批准。

案例覆盖退款期限内/恰好七天/超出一微秒、全额金额上下差一分、已有退款、损坏未核实、数字品类及未来送达；补偿不足/恰好/超出二十四小时、金额及重复补偿、与退款条件的独立性；缺订单澄清前后、依据匹配的转人工；政策含起点不含终点、旧版引用和 UTC 时区等价。

期望按 [v1 业务规格](../business/v1/README.md) 手工核对并保存，没有调用被验证的规则函数生成答案。测试解析现有共享 schema，再调用 BusinessRules.evaluate，逐项比较完整期望并核对输入未变：

```powershell
uv run --no-sync --cache-dir .uv-cache python -m pytest -q tests/unit/test_boundary_cases.py -p no:cacheprovider
```

这是只读资格核对，不创建数据库、不记录批准、不执行业务写入。实际执行仍须提案、人工确认、可信执行器和业务事务；这里不证明确认绑定、改键去重、传输故障恢复或模型/训练效果。`expected` 和核对依据不能作为模型输入或训练轨迹。
